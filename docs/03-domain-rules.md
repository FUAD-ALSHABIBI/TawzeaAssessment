# 03. Domain Rules

> This is the most important document. It defines what an **IT asset** is, what each field means, and how the system calculates values from them. If the code and this document disagree, one of them is wrong: fix the code or update this document.

Each rule is labelled with how it is enforced:

- **Enforced (DB)**: by a database constraint
- **Enforced (API)**: by model validation or controller logic
- **Enforced (UI)**: only in the browser, so a direct API call can bypass it
- **Not enforced**: an expectation that nothing currently checks

## 1. The asset

An **IT asset** is one physical piece of IT equipment owned by the company, such as a laptop, monitor or printer. Each row in `ITAssets` is one physical item.

| Field                    | Meaning                                                     | Required | Rule enforcement |
| ------------------------ | ----------------------------------------------------------- | -------- | ---------------- |
| `Id`                     | System identity of the asset (GUID)                         | Yes      | Enforced (DB): primary key. Generated by `sp_ITAsset_Create` (`NEWID()`); any client value is ignored |
| `Brand`                  | Manufacturer, such as `Dell`, `HP` or `Lenovo`              | Yes      | Enforced (API): `[Required]`, max 100 characters; Enforced (DB): `nvarchar(100)`; Enforced (UI): `required` |
| `SerialNumber`           | Manufacturer's serial number                                | Yes      | Enforced (API): `[Required]`, max 100 characters; Enforced (DB): `nvarchar(100)`, unique index (see rule 1.1); Enforced (UI): `required` |
| `WarrantyExpirationDate` | Last day the manufacturer's warranty covers the asset       | Yes      | Enforced (API): `[Required]`; Enforced (UI): `required` |
| `Status`                 | Where the asset is in its lifecycle (see section 2)         | Yes      | Enforced (API): `[Required]`, must be a valid enum name |
| `CreatedDate`            | When the asset was first recorded in the system             | Yes      | Set by `sp_ITAsset_Create` (`GETDATE()`, DB server time). See rule 1.3 |

### Rules

1.1 **Serial numbers must be unique.** One physical item must not be recorded twice. *Enforced (DB)*: unique index `IX_ITAssets_SerialNumber`. The API answers a duplicate with **409**, and the form shows "An asset with this serial number already exists." The comparison follows the database collation, so case and trailing spaces are ignored (`ABC` = `abc` = `ABC `).

1.2 **Brand is free text.** There is no fixed list of brands. `Dell` and `dell` are stored as typed, but SQL Server's default case-insensitive collation groups them together on the dashboard.

1.3 **`CreatedDate` should never change after creation.** *Enforced (DB)*: `sp_ITAsset_Create` sets it and `sp_ITAsset_Update` never touches it, so any `createdDate` a client sends is ignored.

1.4 **An asset's identity (`Id`) never changes.** Updates are matched by the `Id` in the URL (`PUT /ITAsset/update/{id}`). The request body has no `Id` field.

## 2. Status lifecycle

| Value (API/DB) | Label (UI) | Meaning                                           | Badge colour |
| -------------- | ---------- | ------------------------------------------------- | ------------ |
| `New`          | New        | Received, not yet given to a user                 | Blue         |
| `InUse`        | In Use     | Assigned to and used by someone                   | Green        |
| `Damaged`      | Damaged    | Broken or faulty, awaiting repair or disposal     | Amber        |
| `Disposed`     | Disposed   | Permanently retired (scrapped, sold, written off) | Grey         |

The expected lifecycle is:

```
New ──▶ InUse ──▶ Damaged ──▶ Disposed
          ▲          │
          └──────────┘   (repaired)
```

2.1 **Status is stored and sent as its name**, such as `"InUse"`, never as a number. The enum values in C# (1 to 4) are not used in the database or the API. This keeps the database and API payloads readable without the code.

2.2 **Transitions are not enforced.** Any status can change to any other, including from `Disposed` back to `New`. The diagram above shows intent only.

2.3 **New assets start as `New` by default.** The API requires a status, and the Add form preselects `New`.

## 3. Disposed vs deleted

3.1 **Disposing** an asset (setting `Status = Disposed`) is the normal end of its life. The record is kept for history and still counts in dashboard totals.

3.2 **Deleting** an asset removes the row permanently (hard delete). It is intended for correcting mistakes, such as a duplicate or wrongly entered record, not for retiring equipment.

## 4. Warranty

4.1 **A warranty is expired** when `WarrantyExpirationDate` is before the current moment. Expired dates are shown in red with "(expired)".
- This is calculated **in the browser**, using the user's clock and time zone.
- Because the stored date has no time (midnight), an asset whose warranty ends today shows as expired for all of today.

4.2 **"Expiring this month"** (Dashboard) means `WarrantyExpirationDate` falls within the **current calendar month**: `>= 1st of this month 00:00` and `< 1st of next month 00:00`. "This month" is the DB server's month (`GETDATE()` in `sp_Dashboard_WarrantyExpiringThisMonth`).
- This is calculated **on the server**, using the server's clock.
- It includes dates earlier this month that have already passed, so the table can show some rows marked "(expired)".
- Results are ordered by expiry date, earliest first.

4.3 Warranty rules apply to **every status**, including `Disposed`. Disposed assets still appear in the expiring list.

## 5. Dashboard figures

| Figure                         | Definition                                                         |
| ------------------------------ | ------------------------------------------------------------------ |
| Total Assets                   | Count of all rows in `ITAssets`, any status (including Disposed)   |
| Brands                         | Number of distinct `Brand` groups (collation rules apply, see 1.2) |
| Warranty Expiring This Month   | Count of assets matching rule 4.2                                  |
| Assets by Brand (bar chart)    | Count per brand, largest first                                     |
| Assets by Status (donut chart) | Count per status. Statuses with zero assets are not shown          |
